## 1. 問題：アウトプットが止まる

- 技術的な知見や試行結果が蓄積されているのに、公開や発信が進まない
- アウトプットしようとするたびに強い抵抗を感じ、作業が停止する
- 中間成果物は滞留し、知見は抽出されず、行動そのものが止まる
- 公開して初めて得られる**フィードバック**がなく、思考の偏りに気づけずに独りよがりな理解にとどまる

{/* 皆さんは、勉強したことや試したことがあるのに、それを外に出すとなると急に手が止まってしまう経験はないでしょうか。
私の場合、まさにそれが慢性的な問題でした。技術ブログを書きたい、スライドで発表したいと思っても、
気づけば何も公開できていない——そんな状態が続いていました。
さらに問題なのは、公開しなければフィードバックも得られないことです。反応や指摘をもらうことで自分の理解の歪みに気づき、成長する機会をすべて逃している。非公開のままでは思考が自己完結し、偏った解釈を正す契機が永遠に訪れません。 */}

</SlideCard>

<SlideCard slideTitle={frontmatter.title}>

## 2. 問題の分析：なぜ公開できないのか

- 掘り下げると、一貫した基準が見えた
  - **「今考える限り最も価値が高い状態」** を満たさない成果物は公開に値しない
- 失敗が判明した中間成果物 → 「最善の価値」を持たない → 公開を躊躇
- 将来失敗するかもしれない不確実性だけでも公開が停止する
- 突き詰めれば **「最大の価値を提供しなければならない」という歪んだこだわり**

{/* なぜ公開できないのかを自己分析しました。すると、「今自分が考えうる限り最も価値が高い状態でなければ公開してはいけない」
という暗黙のルールがあることに気づきました。これは一見すると品質へのこだわりのように見えますが、
実は「完璧でなければ価値がない」という思い込みで、自分の行動を止めているだけでした。 */}

</SlideCard>

## 3. 現状分析：既存プラットフォームの比較

</SlideCard>

<SlideCard slideTitle={frontmatter.title}>

### Zenn
- 技術記事・本（Book）に特化 — スライド・ストーリー・スクラップは不可
- エディタは充実、Markdown ベースで書きやすい
- しかし「記事」以外のフォーマットを同じ場所に出せない
- 公開への心理的ハードルが低いのはメリット

</SlideCard>

<SlideCard slideTitle={frontmatter.title}>

### Qiita
- 技術記事専用、Zenn よりさらにフォーマットが限定される
- 最低限の質が担保されている印象が強く、試行錯誤記録には場違い感がある
- アウトプットの動機付けにはなるが、書けるものが限定される

</SlideCard>

<SlideCard slideTitle={frontmatter.title}>

### 総評
- 既存プラットフォームは「書きやすさ」や「公開のしやすさ」に優れる
- しかし、扱えるフォーマットが限定されるため、**複数フォーマットを一貫して出したい** 場合はサービス間の分散が避けられない
- **評価**：「書きたい形式を、同じ基盤で、気軽に出せる」体験が不足している

{/* Zenn と Qiita、それぞれに強みはある。Zenn のエディタ体験は素晴らしく、Qiita のエンゲージメント設計も秀逸だ。
しかし、スライドを出したいなら SlideShare・Google スライド、スクラップ的にメモを残したいなら Scrapbox──と、
フォーマットごとに別のサービスを使わざるを得ない。この「分散」がアウトプットの連続性を断ち切っている。
Isoshigi Info Hub は、この分散を解消し、すべてのフォーマットを同一基盤で扱うことを目指す。 */}

</SlideCard>

<SlideCard slideTitle={frontmatter.title}>

## 4. 解決策：Isoshigi Info Hub

**「自分専用の公開プラットフォーム」を一から構築する**

</SlideCard>

<SlideCard slideTitle={frontmatter.title}>

- サービス分散の解消 → 記事・スライド・ストーリー・スクラップ を **同一基盤** で管理
- 「完璧でなければ出せない」の打破 → 中間成果物から知見を抽出し、**物語として完成させる**サイクル
- 切り替え負荷の排除 → すべて Markdown で執筆し、**書くことだけに集中**できる環境

{/* 使い心地の評価で明らかになった三つの課題に対し、それぞれ具体的な解決手段を組み込んだプラットフォームを一から構築した。
静的サイトジェネレータを基盤に、コンテンツは全てMarkdown + MDXで管理し、ビルド時に記事・スライド・ストーリー・スクラップ をまとめて生成する。
中間成果物は放置せず、そこから抽出した知見を編集・構成して公開する──これをワークフローとして設計した。 */}

</SlideCard>
